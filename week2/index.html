🖥️ Core PC Subsystems

Just like your desktop or laptop at home, a computer system coordinates distinct subsystems:

  • CPU (Central Processing Unit): The brain executing instructions.
  • RAM (Random Access Memory): Ultra-fast volatile temporary workspace.
  • SSD / NVMe Storage: Permanent non-volatile storage for files & OS.
  • Motherboard & Bus: High-speed data highways connecting all parts.
  • I/O Ports: USB, HDMI, and audio ports for human communication.
💡 Fact to Remember: The CPU executes calculations, RAM holds active data temporarily, while the SSD stores your programs permanently even when power is off!

Activity 4 • Architecture Discovery

"Shrinking the Computer": PC vs Microcontroller

What is a microcontroller, and why don't we use desktop PCs inside microwaves or cars?

💡 Core Engineering Definition

Microcontrollers are special-purpose computers designed to control a physical process, machine, or electronic circuit directly.

Instead of multiple separate circuit boards for CPU, RAM, and Storage, an entire computer system is integrated into a single silicon chip.

🤔 Think-Pair-Share Challenge

Before we reveal the technical comparison matrix, discuss with your partner:

  • How does processor speed compare (Gigahertz vs Megahertz)?
  • How does memory scale (Gigabytes vs Kilobytes)?
  • Why would a full Windows OS be bad for an emergency brake controller?
  • How does power consumption compare (300 Watts vs 0.25 Watts)?
💡 Takeaway to Remember: Microcontrollers trade raw computing speed for ultra-low power, low cost, and microsecond deterministic timing.

Subsystem 1

ATmega328P Microcontroller

The brain of the board: an 8-bit AVR RISC microcontroller executing instructions at 16 MHz. Houses 32KB Flash (program storage), 2KB SRAM (variables), and 1KB EEPROM (non-volatile settings).

Key Spec: 28-pin Dual In-Line Package (DIP), 16 MIPS throughput at 16 MHz.
💡 Fact to Remember: Every electronic subsystem on the PCB exists to supply power, clock signals, and protection to the central ATmega328P chip.
Pinout Reference • Electrical Interface

Arduino Uno Rev3 Pinout Architecture

Detailed mapping of digital GPIO, PWM channels (~), analogue inputs, and power rails

📌 Header Pin Categories
Digital I/O (Pins 0 to 13):
Configurable via pinMode() as INPUT or OUTPUT. Pins 0 (RX) and 1 (TX) handle hardware serial.
PWM Pins (~3, 5, 6, 9, 10, 11):
Provide 8-bit Pulse Width Modulation via analogWrite() for motor speed and LED dimming.
Analogue Inputs (Pins A0 to A5):
Connected to 10-bit ADC (0V–5V mapped to integer range 0 to 1023).
Power Header (5V, 3.3V, GND, VIN):
Power supply pins for sensors. VIN accepts 7–12V DC input.
⚠️ Vital Engineering Rule: Every pin has a dedicated function and strict electrical limits (Maximum 20mA recommended continuous current per I/O pin).

Firmware Architecture • Execution Cycle

Arduino Execution Model: setup() vs loop()

Understanding the microcontroller startup lifecycle and continuous execution engine

⚙️ Microcontroller Execution Lifecycle
⚡ Power ON / Reset Button
│ ↓ (Bootloader initializes hardware)
void setup() { ... }
• Runs EXACTLY ONCE at boot/reset
• Configures hardware pin modes (pinMode)
• Initializes Serial communication & sensor calibration
│ ↓ (Enters non-terminating control loop)
void loop() { ... }
• Repeats FOREVER / CONTINUOUSLY
• Polls input sensors (digitalRead)
• Executes decision logic & drives outputs (digitalWrite)
🔬 Key Architectural Differences
void setup()

If you put pin configuration inside loop(), the MCU needlessly reconfigures hardware registers millions of times per second. Keep initialization in setup()!

void loop()

Unlike a desktop C++ main() function that returns 0 and exits to the OS, an embedded microcontroller has no OS to return to. loop() runs continuously until power is removed.

// Behind the scenes in Arduino AVR core:
int main(void) { init(); setup(); for(;;) { loop(); } }
💡 Fundamental Law: setup() prepares and initializes the hardware once; loop() controls the real-time continuous operation forever.

Engineering Rule 2 • Input Circuitry

Design Before Code: Pushbutton & INPUT_PULLUP

Why do floating pins cause random false triggers, and how does internal pull-up solve it?

🔌 Why Use INPUT_PULLUP?

An unconnected digital input pin is floating—it acts like an antenna picking up electromagnetic noise and flipping randomly between 0V and 5V.

pinMode(2, INPUT_PULLUP) connects an internal 20kΩ–50kΩ resistor to 5V.

  • Button Released: Internal resistor pulls pin safely to HIGH (5V).
  • Button Pressed: Switch shorts pin to GND → reads LOW (0V).
📖 Pin Modes Compared
📖 pinMode(pin, mode) Reference ↗
  • INPUT: High impedance state (for external circuits with pull-down resistors).
  • INPUT_PULLUP: Activates internal 5V pull-up (active-LOW pushbutton).
  • OUTPUT: Low impedance state (drives 0V or 5V to LEDs/relays).
💡 Fact to Remember: INPUT_PULLUP saves breadboard space and component cost by eliminating the need for an external physical resistor!
Activity 8 • Digital Input

Digital Input: Controlling LED with a Pushbutton

Reading sensor binary logic states with digitalRead() and conditional branching

💻 Complete Button-Control Sketch
const int BUTTON_PIN = 2;
const int LED_PIN = 13;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP); // Active-LOW
}

void loop() {
  int state = digitalRead(BUTTON_PIN);
  if (state == LOW) { // Pressed
    digitalWrite(LED_PIN, HIGH);
  } else {
    digitalWrite(LED_PIN, LOW);
  }
}

🏭 Industrial Station Logic
const int BTN_START = 2; const int BTN_STOP = 3;
const int LED_RUN = 12;  const int LED_HALT = 13;

void loop() {
  if (digitalRead(BTN_START) == LOW) {
    digitalWrite(LED_RUN, HIGH);  // RUNNING
    digitalWrite(LED_HALT, LOW);
  }
  if (digitalRead(BTN_STOP) == LOW) {
    digitalWrite(LED_RUN, LOW);
    digitalWrite(LED_HALT, HIGH); // HALTED
  }
}
